# Planner 2.0 verification

Version 2.0.0, Android version code 32. Updated 11 November 2026.

## Local checks

- Core: 173 tests, no failures.
- Native/shared sync: 25 tests, no failures; two opt-in external phone fixtures skipped.
- Shared UI/data: 147 tests, no failures, including Today agenda filtering, repeated Enter-to-add focus retention and five-destination navigation at normal/large text.
- Desktop: 28 tests, no failures; two opt-in icon/data tooling fixtures skipped.
- Kotlin style check passes.
- Android lint: zero errors, 23 warnings and one hint.
- Android QA APK builds; package identity is `dev.fourthbreakfast.planner.demo.qa`, version 2.0.0/code 32. This is not a production download.
- Windows setup builds. Packaged runtime starts with isolated data; the second launch exits cleanly, signals the first process, and the first consumes the reveal request. Both test processes are cleaned up.
- Documentation images are renders from the application with test fixtures, not generated concepts. Local README/development/design/release-document links resolve.
- Release workflows pass actionlint and static Bash/PowerShell syntax checks.
- Android 16/API 36 x86-64 emulator: QA cold launch, all five destinations, Enter-to-add and three consecutive task additions pass. Seven on-device database migration tests pass. ARM64 native sync is not exercised by this emulator; the physical phone was not modified.

Local JVM checks use the available JDK 25; production CI and packaged runtimes use Java 21. Source and fixture changes after an earlier pass were rebuilt and checked again.

## Production preflight

- [Signed multiplatform preflight](https://github.com/fourthbreakfast/planner/actions/runs/42936149904) checks the application on Windows and Linux with their real native sync engines.
- Production Android APK identity and the pinned signing certificate are verified. The Windows setup builds and its packaged runtime passes the isolated-data startup and second-launch checks.
- Linux Debian and portable packages build. The Debian package's bundled Syncthing reports its version, and the packaged application starts under Xvfb and creates its isolated database. Portable launcher paths and executable permissions are checked during packaging.
- Tag publication repeats these gates, requires all four platform assets, generates checksums, and verifies uploaded-draft asset sizes and SHA-256 digests before publication. The resulting files are attached to [v2.0.0](https://github.com/fourthbreakfast/planner/releases/tag/v2.0.0).

## Scope and remaining limits

- Linux native Wayland and a new 2.0 installation on the physical ARM64 phone have not been verified.
- WinGet manifests can be generated and validated after the production installer is published; catalog acceptance is separate.

Earlier physical-phone sync evidence is recorded in the [phone verification guide](../phone-sync-qa.md). It does not claim that a new 2.0 build has been installed on that phone.
